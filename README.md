# Bowling Player

[日本語](README.md) | [English](README.en.md)

Minecraft 1.20.1 向けの Fabric / Forge MOD です。プレイヤーが通常・ボウリングのピン・ボールの姿を切り替えられる本体 MOD `bowlingplayer` と、ケイドロを運営するアドオン `bowlingplayergame` が含まれます。

## 導入

- Fabric: Fabric Loader と Fabric API を入れ、`fabric/build/libs/` の本体 JAR を `mods` フォルダーに配置します。ケイドロで遊ぶ場合は `game-fabric/build/libs/` のアドオン JAR も配置します。
- Forge: Forge を入れ、`forge/build/libs/` の本体 JAR を `mods` フォルダーに配置します。ケイドロで遊ぶ場合は `game-forge/build/libs/` のアドオン JAR も配置します。
- 本体とアドオンは同じローダー用のものを使用してください。アドオンには本体 MOD が必要です。
- 各 `build/libs/` では、ファイル名が `-sources.jar` や `-javadoc.jar` で終わらない JAR を選んでください。

## ビルド

JDK 17 を使用します。リポジトリ直下で `./gradlew build`（Windows は `.\gradlew.bat build`）を実行すると、本体とアドオンの Fabric / Forge 版をまとめてビルドできます。GitHub Actions でも push と pull request ごとに同じビルドを実行します。GitHub Release を公開すると、そのタグのソースから4種類の JAR をビルドして Release に添付します。

## Bowling Player Game（ケイドロ）アドオン

以下は [game-common/README.md](game-common/README.md) にあるゲーム運営ガイドです。

`bowlingplayergame-fabric-1.20.1-1.0.0.jar` または `bowlingplayergame-forge-1.20.1-1.0.0.jar` で動作する、ケイドロ（鬼ごっこ）ゲーム運営用アドオンです。ファイル名のバージョン部分はビルド時の設定によって変わります。
本体MOD `bowlingplayer` に依存し、ピン側（逃げる）＝赤[Pin]、ボール側（追う）＝青[Ball] として対戦します。

- 対象: Minecraft 1.20.1 / Fabric・Forge
- 前提MOD: `bowlingplayer`（本体）
- コマンドルート: `/bpg`（OP / 権限レベル2）

## 1. ゲームの流れ

1. `/bpg config ...` で展開位置・牢獄・各種設定を行う（初回のみ。設定は `<ワールド>/bowlingplayergame.json` に保存）。
2. `/bpg team auto` でチーム分け（赤:青 = 3:1）。運営は `/bpg team set <player> staff`。
3. `/bpg start` で開始。
   - 赤チームが先に展開地点へ出現（`Game Start` タイトル＋金床設置音）。
   - 青チームは待機（スペクテイター）。
   - **30秒後**（既定）に青チームが展開（出動）。出動の**10秒前から全員に秒読みカウントダウン**（タイトル＋音）が表示され、出動時に「青チーム出動！」＋効果音。
4. 赤は捕まると牢獄へ即リスポーン。仲間に救出されると復帰。青が死ぬと一定時間スペクテイター後、**青の展開地点**に復帰。
5. 終了条件:
   - **赤が全員捕獲** → 青チーム（Ball）の勝ち。
   - **制限時間切れ（既定30分）** → 赤チーム（Pin）の勝ち。
   - 終了時に `Game End` タイトルと結果・スコアを表示（金床使用音）。**全員スペクテイター**になる。
6. `/bpg stop` で状態をリセット（次のゲームへ）。

## 2. 実運用ガイド（コマンドを打つ順番）

実際の進行で「どの順番でコマンドを打つか」をまとめます。`<>` は置き換え、`[]` は任意です。

### A. 初回だけ行う準備（ワールドごとに1回）

座標は **コマンド実行者が立っている位置** が登録されます。実際にその場所へ移動してから打ちます。

1. 赤チームの展開地点へ移動して `/bpg config reddeploy 5`（末尾の数字は散らばり半径。不要なら `/bpg config reddeploy`）
2. 青チームの展開地点へ移動して `/bpg config bluedeploy`
3. 牢獄にする場所へ移動して `/bpg config jail add`（**複数箇所**にしたい場合は移動しながら繰り返す）
4. 必要なら数値を調整（例 制限時間20分: `/bpg config timelimit 1200`、比率: `/bpg config ratio 3 1`）
5. `/bpg config show` で内容を確認（展開・牢獄が「未設定」でないこと）

> 設定は `<ワールド>/bowlingplayergame.json` に保存されるので、サーバーを再起動しても残ります。次回以降この準備は不要です。

### B. 1ゲームの運営フロー（毎回）

1. 参加者を全員ログインさせる
2. 運営がいれば先に外す: `/bpg team set <運営の名前> staff`
3. チーム分け: `/bpg team auto`（運営以外の未所属を 3:1 で振り分け）
4. 人数確認: `/bpg status`（赤・青・運営の人数を表示）
5. 開始: `/bpg start`
   - 赤が展開 → 既定では30秒後に青が出動 → あとは自動進行
6. 勝敗は自動判定（全員捕獲で青／時間切れで赤）。`Game End` と結果が表示される
7. 片付け: `/bpg stop`

### C. 続けてもう1戦（繰り返し）

ゲームが自動終了（または `/bpg stop`）した後、次のように回します。

- **同じチームでもう1戦**: `/bpg stop` → `/bpg start`
- **赤青を入れ替えてもう1戦**: `/bpg stop` → `/bpg team swap` → `/bpg start`
- **メンバーを組み直す**: `/bpg stop` → `/bpg team auto force`（運営以外を全員再シャッフル）→ `/bpg start`

> `start` を実行すると捕獲数・救出数・牢獄状態などは毎回リセットされます。前回スコアを見たい場合は次の `start` 前に `/bpg score` を確認してください。

### D. 途中で中止する

- `/bpg stop` でいつでも中止できます（勝敗は付きません）。
  ボスバーの消去・設置済みクモの巣の撤去・PIN/BALLモードの解除（NORMALへ）まで自動で行います。

### E. 設定をやり直す（ミスした時）

1. `/bpg stop`（進行中なら止める）
2. 直したい設定を打ち直す（例: 牢獄を作り直す → `/bpg config jail clear` → 各地点で `/bpg config jail add`）
3. `/bpg config show` で確認 → `/bpg start`

### F. よくあるトラブル

| 症状 | 対処 |
|---|---|
| `start` が「設定が未完了」で失敗 | `/bpg config show` で 赤展開・青展開・牢獄数 が設定済みか確認。未設定なら A を実施 |
| プレイヤーのモードがおかしい / 動けない | `/bpg stop` で一度リセットしてから team 設定をやり直す |
| 途中から参加した人がチームに入っていない | ゲーム中の新規参加者は自動編成されません。`/bpg stop` → `/bpg team auto` し直すか、`/bpg team set <名前> red\|blue` で手動追加 |
| 特定の人だけチームを変えたい | `/bpg team set <名前> red\|blue\|staff\|none` |

### コピペ用クイックスタート

```
# 準備（各地点に立って実行、初回のみ）
/bpg config reddeploy 5
/bpg config bluedeploy
/bpg config jail add

# 毎回
/bpg team auto
/bpg start

# 終わったら
/bpg stop
```

## 3. コマンド一覧（`/bpg`）

| コマンド | 説明 |
|---|---|
| `team auto` | チーム未所属のプレイヤーのみ、比率に従って赤/青へ割り振る |
| `team auto force` | 運営以外の全員を再シャッフルして割り振る |
| `team set <players> red\|blue\|staff\|none` | 指定プレイヤーのチームを設定／解除 |
| `team swap` | オンラインの赤チームと青チームを入れ替え |
| `team clear` | 全員のチーム割り当てを解除 |
| `start` | ゲーム開始（設定が未完了だと失敗） |
| `stop` | ゲーム終了・状態リセット |
| `status` | 現在のフェーズと各チーム人数を表示 |
| `score` | 青の捕獲数・赤の救出数を表示 |
| `config show` | 現在の設定を一覧表示 |
| `config <キー> <値>` | 数値設定の変更（下表） |
| `config ratio <赤> <青>` | チーム人数比を設定 |
| `config reddeploy [半径]` | 赤チーム初期展開位置を**実行者の現在地**に設定（半径で散らばり指定） |
| `config bluedeploy` | 青チーム初期展開位置を実行者の現在地に設定 |
| `config jail add` | 牢獄リスポーン位置を実行者の現在地に追加（複数可） |
| `config jail clear` | 牢獄位置を全消去 |
| `config items <red\|blue> steak <0-64>` | チームごとの初期ステーキ数 |
| `config items <red\|blue> cobwebs <0-64>` | チームごとのクモの巣数（初期＆リス時補充） |
| `config items <red\|blue> detector <true\|false>` | チームごとに探知機を持たせる／持たせない |
| `config items <red\|blue> speed <true\|false>` | チームごとに加速の羽を持たせる／持たせない |
| `config items <red\|blue> add <item> <count>` | 任意のアイテムを初期配布に追加（例 `minecraft:golden_apple 2`） |
| `config items <red\|blue> removeextra <index>` | 追加アイテムを番号指定で削除（番号は `config show` で確認） |
| `config items <red\|blue> clearextra` | 追加アイテムを全消去 |

`config <キー> <値>` で設定できる数値キー: `timelimit`, `bluedelay`, `itemcooldown`,
`speedduration`, `speedlevel`, `detectrange`, `cobwebdespawn`, `bluespectator`, `ballsize`, `pinsize`, `damage`

## 5. アイテム仕様

開始・展開時に配布。`keepInventory` のため死亡しても保持され、リス時にクモの巣を補充します。
配布内容は**赤・青それぞれ個別に設定可能**（`config items <red|blue> ...`）。

既定の配布: 赤＝ステーキ＋クモの巣、青＝ステーキ＋探知機＋加速（チーム別に変更可）。

| アイテム | 使用素材 | 既定 | 効果 |
|---|---|---|---|
| ステーキ | 焼いた牛肉 | ×64 | 食料（個数を設定可、0で無し） |
| 設置用クモの巣 | クモの巣 | 赤×5 | 右クリックで**視点先のブロックの手前（1つ手前の空気ブロック）**にレイトレースで設置。アドベンチャーでも内部処理で設置。一定時間で消滅（個数を設定可、0で無し） |
| 探知機 | エコーシャード | 青のみ | クールタイムごとに、周囲（既定60ブロック）の赤青プレイヤーを発光させる。**発光は使用者本人にしか見えない**（有/無を設定可） |
| 加速の羽 | 羽根 | 青のみ | クールタイムごとに、一定時間（既定15秒）移動速度上昇（有/無を設定可） |

- アイテムは**NBTタグ `BpgItem` で判別**（カスタムアイテム登録なし／データパック不要）。
- 探知・加速は消費されず、クールタイム（既定2分）で再使用可能。
- 配布アイテムは**固定スロット（ステーキ=0/クモの巣=1/探知機=2/加速=3）に固定**され、ゲーム中は移動・並べ替えできません。無効にしたアイテムのスロットは空のままです。
- **追加アイテム（拡張可能）**：`config items <red|blue> add <item> <count>` で任意のバニラアイテムを初期配布に追加できます。追加分は固定スロットの後（空きスロット）に入り、コード変更なしでキットを拡張できます。

## 6. 仕様の追加内容（実装上の判断・詳細）

ベース仕様に対し、以下を明確化・補完して実装しています。挙動を変えたい場合はここを調整します。

1. **コマンドルートは `/bpg`**（OP / 権限レベル2必須）。
2. **位置設定はコマンド実行者の現在地**を使用（`reddeploy` / `bluedeploy` / `jail add`）。ディメンションも実行者の居る次元を記録。
3. **gamerule はゲーム開始時に自動設定**：`keepInventory=true`, `fallDamage=false`, `doImmediateRespawn=true`（赤の即リス＝死亡画面なし）。
4. **アイテムを捨てられない仕様（完全ブロック）**：ドロップ操作（Qキー）自体を無効化し、**地面に一切落とさない**。Fabricは `Player#drop` への Mixin（`PlayerDropMixin`）で入口をキャンセル、Forgeは `ItemTossEvent` をキャンセルしてインベントリへ即時返却。アイテムがインベントリから出る前に阻止するため、消失リスクや誤回収はありません。
5. **配布アイテムの移動禁止（固定スロット）**：ステーキ＝スロット0、クモの巣＝1、探知機＝2、加速の羽＝3 に固定。毎tickで定位置に戻すため、インベントリ内で並べ替え・別スロットへの移動ができない（他スロットは自由）。
6. **クモの巣の設置位置はレイトレース**：視点の先のブロックに対し、**その手前（1つ手前）の空気ブロック**に設置（最大5ブロック）。空気・当たり判定のないブロックにのみ設置。
7. **効果音**：開始時は**金床の設置音**、終了時は**金床の使用音**を全員に再生。青出動カウントダウンは経験値取得音、出動時はレベルアップ音。
8. **牢獄中の赤プレイヤー**はアドベンチャーのため移動可能だが、「捕獲状態」フラグが救出まで残る。死亡時は牢獄リス位置（複数指定時はラウンドロビン）に出現。
9. **救出**：生存（非捕獲）の赤が、捕獲中の赤を殴ると、対象を殴った側の位置へ復帰させ、救出者の救出数 +1。
10. **青チームの死亡**：`bluespectator` 秒間スペクテイターになり、その後**青チームの展開地点**にアドベンチャーで復帰。
11. **スコア（バニラのスコアボード）**：青＝捕獲数（objective `bpg_kills`）、赤＝救出回数（objective `bpg_rescues`）をバニラのスコアボード機能で記録。**ゲーム開始時に両 objective を削除→再作成**（スコアをクリア）。サイドバーは**ゲーム終了後のみ表示**し、捕獲数↔救出数を5秒ごとに交互表示（開始前・ゲーム中は非表示）。`stop` でサイドバーを解除。終了時のチャットには各チーム**上位5人**のスコアを表示。`/bpg score` でも確認可（こちらは全員）。スコアボードはワールドに保存されるため再起動後も保持。
12. **探知は本人のみ**：探知機の発光は、エンティティのフラグを**使用者本人だけにパケット送信**して実現（他プレイヤーには見えない）。
13. **終了時は全員スペクテイター**：`Game End` 時に全プレイヤーをスペクテイターにし、PIN/BALLモードを解除して結果を観戦させる。
14. **スペクテイターの薄い描画**：スペクテイターの赤/青プレイヤーはカスタムのボール/ピン描画をスキップし、バニラの半透明スペクテイター描画に任せる（本体MOD `PlayerRendererMixin` を修正）。
15. **チーム**：`bpg_red`[Pin]/`bpg_blue`[Ball]/`bpg_staff`[運営] のバニラのスコアボードチームを使用。色付け・フレンドリーファイア無効。運営はスペクテイター。
16. **本体モード連動**：赤に PIN モード、青に BALL モードを付与（ボールがピンを当てる本体の当たり判定を利用）。`stop` で NORMAL に戻す。
17. **ホットバー表示（合成・追記方式）**：残り時間・出動/復帰までの秒数・各種通知（捕獲/救出/探知/クールダウン等）を**1本のアクションバーに合成**して送信（`残り MM:SS ｜ 復帰まで N秒 ｜ 通知`）。別々に送らないため一瞬で消えません。通知は数秒で消え、残り時間は残り続けます。青チームはスペクテイター中（初期待機・死亡後復帰待ち）にホットバーへ「出動まで/復帰まで N秒」を表示。生存者数はボスバー、`Game Start`/`Game End` はタイトル表示。
18. **クラッシュ復帰（状態永続化）**：進行中のゲーム状態を `<ワールド>/bowlingplayergame_state.json` に保存し、サーバー再起動時に自動再開。下記参照（スコアはスコアボード側で永続）。

## 7. クラッシュ復帰（状態の永続化）

サーバーが途中で落ちても、再起動時に**進行中のゲームを自動で再開**します。

- **保存対象**: フェーズ、残り制限時間、青の展開済みフラグ、牢獄状態、スコア（捕獲/救出）、アイテムのクールタイム、青の復帰待ち、設置中クモの巣（位置＋残り時間）。
- **保存タイミング**: ゲーム開始時・青出動時・死亡/救出時・**5秒ごとの自動保存**・正常終了（shutdown）時。最大でも約5秒前の状態まで復元できます。
- **再アンカー**: 残り時間やクールタイムは「絶対tick」ではなく「経過/残りtick」で保存し、再起動後の最初のtickで現在のサーバーtickに再計算します（`server.getTickCount()` は再起動でリセットされるため）。
- **保存先**: `<ワールド>/bowlingplayergame_state.json`（**アトミック書き込み**で保存中クラッシュでも破損しない）。ゲームが正常終了/`stop` すると削除されます。
- **再接続/途中参加**: 参加者が再ログインすると、ボスバー再表示・PIN/BALLモードの再付与を自動で行います。
- **同時に残るもの**: チーム分け（scoreboard）・各プレイヤーのゲームモード・gamerule・設置済みクモの巣ブロックはバニラ機能で元々保存されます。

> ゲームを途中で完全に中止したい場合は `/bpg stop`（状態ファイルも削除されます）。
